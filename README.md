# SCSE Agentic Software Engineering Project

This project is for the SCSE Agentic Software Engineering practices.

The project uses a local Qwen model through Ollama to convert a human-written
robot navigation brief into validated requirements, a navigation plan,
generated navigation logic, tests, simulation reports, and IR-SIM benchmark
reports.

## File Descriptions

### `brief.txt`

This is the original human-written brief provided for the robot navigation
task.

It describes the following customer requirements:

- the robot receives information about blocked directions
- the robot may receive information about the goal direction
- the robot should prefer moving toward the goal when it is safe
- the robot must never move into a blocked direction
- the robot must stop if no safe direction is available
- the navigation component will be tested in multiple simulated environments

### `brief_to_req.py`

This is the first-stage experiment script.

It reads `brief.txt`, sends the brief to the local `qwen3:8b` model through
Ollama, and prints a human-readable software requirements analysis.

This script satisfies the instruction to first ask Qwen to read the brief and
produce software requirements from the text.

### `robot_requirements.txt`

This file stores one output produced by running `brief_to_req.py`.

It is a human-readable requirements analysis generated by Qwen. It is useful
for checking whether Qwen understood the original brief correctly.

This file is not the final machine-readable output. The final structured output
is `artifacts/requirements.json`.

### `analyst_agent.py`

This is the main Analyst Agent implementation.

It contains:

- `run_analyst(brief_text)`: sends the brief to Qwen, receives JSON text,
  parses it, validates it, and returns the validated requirements
- `validate_requirements(result)`: checks that the generated requirements have
  the exact structure required by the assignment

The Analyst Agent requires Qwen to return only valid JSON with exactly these
four keys:

- `goal`
- `allowed_actions`
- `safe_stop`
- `avoid_obstacles`

The only allowed robot actions are:

- `FORWARD`
- `LEFT`
- `RIGHT`
- `STOP`

### `run_analyst.py`

This is the main runner for the formal Analyst Agent workflow.

It:

1. reads `brief.txt`
2. calls `run_analyst()`
3. creates the `artifacts` folder if needed
4. saves the validated requirements to `artifacts/requirements.json`

### `artifacts/requirements.json`

This is the final validated output of the Analyst Agent.

It contains the structured requirements generated by Qwen and checked by the
Python validation function. This JSON file is intended to be used by later
navigation logic, test generation, or other agents.

## Requirements

This project expects:

- Python 3.12
- uv
- Ollama
- the local Ollama model `qwen3:8b`
- the Python package listed in `requirements.txt`

The scripts use the `ollama` Python package to call the local Ollama service.
Ollama must be running locally before the scripts are executed.

## How To Run

Create the virtual environment with uv:

```powershell
uv venv --python "C:\Program Files\Python312\python.exe" .venv
```

Install the Python dependency:

```powershell
uv pip install -r requirements.txt
```

Run the first-stage requirements experiment:

```powershell
.\.venv\Scripts\python.exe brief_to_req.py
```

Run the formal Analyst Agent workflow:

```powershell
.\.venv\Scripts\python.exe run_analyst.py
```

After the formal workflow runs successfully, the final output is saved at:

```text
artifacts/requirements.json
```

## Expected JSON Format

The final JSON should follow this structure:

```json
{
  "goal": "Navigate toward the goal location",
  "allowed_actions": ["FORWARD", "LEFT", "RIGHT", "STOP"],
  "safe_stop": true,
  "avoid_obstacles": true
}
```

The exact wording of `goal` may vary because it is generated by Qwen, but the
JSON keys, data types, and allowed actions must match the required structure.

## Local Check

Run this command from the project root:

```powershell
.\.venv\Scripts\python.exe run_analyst.py
```

If the workflow succeeds, the terminal should print a message similar to:

```text
Saved validated requirements to D:\agentic_se\artifacts\requirements.json
```

Then open `artifacts/requirements.json` and confirm that it is valid JSON with
only the four required fields.

## Integration and Simulation Workflow

The current project also includes the Integration and Simulation assignment.

Run the full orchestrated pipeline with:

```powershell
.\.venv\Scripts\python.exe main.py
```

The orchestrator runs:

1. Analyst Agent
2. Planner Agent
3. Developer Agent
4. Test Agent
5. Generated pytest tests
6. Simple simulation
7. Reviewer Agent
8. IR-SIM benchmark
9. Benchmark Reviewer Agent
10. Developer Revision Agent if revision is needed

All pipeline events are written to:

```text
trace.log
```

Run the simple simulation only:

```powershell
.\.venv\Scripts\python.exe runner.py
```

Run the IR-SIM benchmark only:

```powershell
.\.venv\Scripts\python.exe benchmark_irsim.py
```

Run a visual IR-SIM world manually:

```bash
./run_visual.sh irsim_worlds/world_easy.yaml
./run_visual.sh irsim_worlds/world_medium.yaml
./run_visual.sh irsim_worlds/world_difficult.yaml
./run_visual.sh irsim_worlds/world_custom.yaml
```
