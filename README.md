# SCSE Requirements Engineering Agent

This project converts a human-written robot navigation brief into explicit
software requirements by using a local Qwen model through Ollama.

The project is for the SCSE Requirements Engineering practice. The main goal is
to show how an Analyst Agent can read natural language requirements and produce
a validated JSON requirements file.

## Project Structure

```text
agentic_se/
  artifacts/
    requirements.json
  analyst_agent.py
  brief.txt
  brief_to_req.py
  README.md
  robot_requirements.txt
  run_analyst.py
```

## File Descriptions

### `brief.txt`

This is the original human-written brief for the robot navigation task.

It describes that the robot:

- receives information about blocked directions
- may receive information about the goal direction
- should prefer moving toward the goal when safe
- must never move into a blocked direction
- must stop when no safe direction is available
- will be tested in multiple simulated environments

### `brief_to_req.py`

This is the first experiment script.

It reads `brief.txt`, sends the brief to the local Qwen model through Ollama,
and prints a human-readable software requirements summary.

This file is used to satisfy the instruction to first ask Qwen to read the
brief and produce software requirements from the text.

### `robot_requirements.txt`

This file stores one output produced by running `brief_to_req.py`.

It is a text record of Qwen's first-stage requirements analysis.

### `analyst_agent.py`

This is the main Analyst Agent implementation.

It contains:

- `run_analyst(brief_text)`: sends the brief to Qwen, receives JSON text,
  parses it, validates it, and returns validated requirements
- `validate_requirements(result)`: checks that the generated requirements have
  the exact required structure

The Analyst Agent requires Qwen to return only valid JSON with these keys:

- `goal`
- `allowed_actions`
- `safe_stop`
- `avoid_obstacles`

The allowed robot actions are:

- `FORWARD`
- `LEFT`
- `RIGHT`
- `STOP`

### `run_analyst.py`

This is the main runner script.

It:

1. reads `brief.txt`
2. calls `run_analyst()`
3. creates the `artifacts` folder if needed
4. saves the validated requirements to `artifacts/requirements.json`

### `artifacts/requirements.json`

This is the final validated output of the Analyst Agent.

It contains the structured requirements generated by Qwen and checked by the
Python validation function.

### `.gitignore`

This file prevents local development files from being uploaded to GitHub.

It excludes the virtual environment, Python cache files, and test cache files.

## Requirements

The project expects:

- Python 3.12
- uv
- Ollama
- the local Ollama model `qwen3:8b`

The scripts call the local Ollama API at:

```text
http://localhost:11434/api/generate
```

## How To Run

Create the virtual environment with uv:

```powershell
uv venv --python "C:\Program Files\Python312\python.exe" .venv
```

Run the first-stage requirements experiment:

```powershell
.\.venv\Scripts\python.exe brief_to_req.py
```

Run the final Analyst Agent:

```powershell
.\.venv\Scripts\python.exe run_analyst.py
```

After running the final script, check:

```text
artifacts/requirements.json
```

## Expected Final JSON Format

```json
{
  "goal": "Navigate toward the goal location",
  "allowed_actions": ["FORWARD", "LEFT", "RIGHT", "STOP"],
  "safe_stop": true,
  "avoid_obstacles": true
}
```

The exact wording of `goal` may vary because it is generated by Qwen, but the
JSON keys, value types, and allowed actions must match the required structure.
